# BLUEPRINT — 구조적 지혜 (성장 메뉴)

검증된 운영 에이전트 시스템이 오랜 회고로 정착시킨 구조적 결정을, 지식노동용으로 일반화한
청사진.
"지금 다 지어라"가 아니다. 각 결정은 필요 신호가 보일 때 how-to-grow 절차로 하나씩
실체화한다.
각 항목: 무엇 / 왜(고민) / 심는 신호 / 심는 법.

## 1. SSoT + 항목별 플래그 + 롤업
- 무엇: 논점을 한 파일(brief)에 두고 항목별 단계 플래그를 매긴다. 단계 status는 롤업으로 기계
판정.
- 왜: 진행상태를 기계가 계산 → 착각·누락 방지. 산출물·작성자 여럿일 때 유일 진실 소스로 충돌
방지.
- 신호: 논점이 10개 넘거나 "무엇이 안 끝났나"를 매번 손으로 셀 때.
- 법: brief.md → brief.json 승격 + 항목 플래그 필드(아직 CLI 없이 직접 편집).

## 2. 기계 렌더 vs 사람 편집 분리
- 무엇: 문서를 SSoT에서 자동 생성, 사람은 지정된 화이트리스트 섹션만 수정.
- 왜: 자동/수기 혼합 시 재생성으로 사람 작업 유실·불일치. 경계 명시로 둘 다 안전.
- 신호: SSoT↔문서 불일치 혼란이 반복될 때.
- 법: render 스크립트로 brief.json→brief.md + 문서에 "## 사람 편집 영역" 지정.

## 3. SSoT는 CLI로만 변경 + 훅 강제
- 무엇: SSoT 직접 편집 차단, 전용 CLI로만.
- 왜: 직접 손대면 스키마·롤업 깨짐. 변경 경로를 하나로 좁혀 무결성 보장.
- 신호: 손편집으로 SSoT 깨지는 사고 2회 이상.
- 법: .claude/scripts/ CLI + .claude/hooks/pre-write.js 차단.

## 4. 단일 검증 게이트 + 폴백
- 무엇: 검증을 한 게이트(/check 확장)로 모음. 외부 검증기 없으면 내부 폴백.
- 왜: 흩어지면 무엇이 검증됐는지 추적 불가. 한 입구+폴백이면 항상 최소 검증.
- 신호: 오류가 검수를 통과해 나가는 일이 반복될 때.
- 법: /check를 게이트로 승격(근거+품질 통합), 실패 시 재작업 목록 반환.

## 5. 컨텍스트 격리 위임
- 무엇: 무거운 작업을 서브에이전트에 위임, 메인엔 압축 결과만.
- 왜: 원자료·중간물이 메인에 쌓이면 한도초과·품질저하. 격리하면 메인은 결론만.
- 신호: 리서치 원문·덤프로 컨텍스트가 자주 꽉 찰 때.
- 법: .claude/agents/에 researcher/reviewer + 부팅 시퀀스 + 위임 규칙 1장.

## 6. 역할별 쓰기 권한
- 무엇: 누가 어느 폴더에 쓸 수 있는지 한 곳에 정의 + 훅 강제.
- 왜: 아무 데나 쓰면 산출물 구조가 무너진다.
- 신호: 파일이 엉뚱한 위치에 생기는 일이 반복될 때.
- 법: .claude/lib/role-permissions.js + pre-write 훅.

## 7. 조건부 룰 로딩 (컨텍스트 절감)
- 무엇: 규칙을 "항상 로드"와 "특정 파일 열 때만 로드"로 나눔.
- 왜: 다 늘 주입하면 낭비. 자주 안 쓰는 건 필요할 때만. (BLUEPRINT가 @import 안 되는 이유.)
- 신호: 규칙이 늘어 매 세션 프리앰블이 무거워질 때.
- 법: 항상-로드는 @import, 조건-로드는 훅이 경로 매칭 시 주입.

## 8. 팀 단위·다중 작성자 전제
- 무엇: "혼자 쓴다"가 아니라 여러 사람 동시 작업 가정.
- 왜: ID 충돌·머지 충돌이 팀에선 사고. 순번 ID 대신 타임스탬프 ID로 원천 차단.
- 신호: 두 사람 이상 공유 시작(= git 공유 시점).
- 법: 산출물 id를 날짜+시각 등 충돌 없는 방식, 로컬 전용 파일은 gitignore 분리.

## 9. 자기개선 + 메모리 (이미 씨앗에 있음)
- 무엇: 실패를 로그하고 반복되면 승격 / 지속 사실은 메모리에.
- 왜: 스스로 자라는 유일한 동력.
- 상태: 이미 있음(how-to-grow). 규모 커지면 활동·부하 리포트로 확장.

## 권장 성장 순서
1(SSoT) → 4(게이트) → 2(렌더분리) → 5(위임) → 3·6(훅 강제) → 7(조건 로딩).
8(팀 전제)은 git 공유 즉시. 3·6(훅 강제)은 사고가 실제로 난 뒤에만.

## 부록 — ACE 부품 카탈로그 (성장 메뉴의 실제 재고)

이 씨앗을 ACE(`ace init --pack seed`)로 심었다면, 위 결정 상당수는 이미 검증된 부품이
ACE 레포(~/.ace/)에 있다. 신호가 오면 처음부터 만들지 말고 아래에서 가져와
지식노동 용어로 다듬어 심어라.

| 결정 | ACE 부품 위치 |
|------|---------------|
| 1. SSoT + 플래그 + 롤업 | `workspace/tasks/taskDetail.json`·`taskIndex.json` 패턴 (dev 팩 참고) |
| 4. 단일 검증 게이트 | `packs/dev/agents/gate.md`, `packs/biz/skills/judge/` |
| 5. 컨텍스트 격리 위임 | `packs/biz/agents/researcher.md`, `packs/dev/agents/reviewer.md` |
| 3·6. 훅 강제 | `core/hooks/` (task-pre-write.js, task-post-write.js, hooks.yaml) |
| 7. 조건부 룰 로딩 | `core/hooks/hooks.yaml`의 경로 매칭 구조 |

가져오는 법: 해당 파일을 이 프로젝트 `.claude/` 아래로 복사한 뒤 다듬는다.
(추후 `ace grow <부품>` 명령으로 자동화 예정 — 고도화 2단계.)
